在执行任何涉及代码写入的任务时，启用 `architecture-change-review` Skill 的阶段性复盘协议：任务第一次编辑前先 `baseline`（已有状态勿覆盖），每次完成有意义的批量编辑、可测试的功能子阶段后执行 `check`；累计 ≥5 个有效文件或 ≥1000 行增删时在最近安全节点 `collect` 并由 Agent 填写真实架构/业务证据后 `render`；≥10 文件或 ≥2000 行尽快复盘；API/schema/权限/架构边界变更即使未到阈值也通过 `check --critical` 标记；独立功能完成和最终交付用 `collect --force`。整个任务结束提供 `.agent-change-review/reports/index.html`。报告简洁、真实、业务结果与技术机制交叉，必须先定位自顶向下的系统模块影响，再展示端到端核心链路 Before/After，不能只列文件 diff。此规则适用于跨上下文压缩与长任务续跑，不要重置已有 Checkpoint。
